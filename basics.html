Section 1

HTTP Basics

HTTP gives browsers and servers a shared way to exchange web resources and information.

What problem does HTTP solve?

Before a browser can display a web page, it needs a standard way to ask a server for files or data. HTTP defines the structure of requests and responses, including methods, headers, status codes, and sometimes a message body.

For example, a browser may request /index.html. The server can respond with the HTML document and information about the content type.

The request–response cycle

  1. A user enters a URL or clicks a link.
  2. The browser finds the server and establishes a suitable connection.
  3. The browser sends an HTTP request.
  4. The server processes the request and sends an HTTP response.
  5. The browser uses the response to display the page and may request more resources, such as CSS, JavaScript, and images.

Common HTTP methods

MethodCommon purpose
GETRetrieve a resource.
POSTSend data to a resource, often to create or process something.
PUTReplace a resource with the supplied representation.
PATCHMake a partial change to a resource.
DELETEAsk the server to delete a resource.
HEADRequest headers similar to GET, without the response body.

Common response status codes

  • 200 OK: the request succeeded.
  • 301 or 302: the resource is redirected.
  • 400 Bad Request: the request could not be processed as sent.
  • 401 Unauthorized / 403 Forbidden: authentication or permission is missing or denied.
  • 404 Not Found: the requested resource could not be found.
  • 500 Internal Server Error: the server encountered an unexpected problem.
