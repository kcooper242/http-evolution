Study guide

Seven Key Concepts

These terms help explain how HTTP works and why its newer versions were developed.

1. Client

A program, usually a browser or app, that sends a request to a server.

2. Server

A system or software that receives requests and sends responses.

3. Header

Metadata attached to a request or response, such as content type or caching instructions.

4. Statelessness

HTTP does not automatically remember earlier requests. Web applications can add state using cookies, sessions, authentication, and databases.

5. TLS and HTTPS

HTTPS carries HTTP over a connection protected by TLS, which helps protect data from being read or changed in transit.

6. Multiplexing

Multiplexing allows multiple independent streams to share a connection. HTTP/2 introduced this over one TCP connection.

7. QUIC

QUIC is the transport protocol used by HTTP/3. It supports independent streams and integrates TLS 1.3 into connection setup.

More to explore

HTTP caching lets a browser or intermediary reuse a stored response instead of requesting the same resource again. APIs also use HTTP to exchange data, often in JSON format.

These ideas connect HTTP to website speed, security, and modern applications.
